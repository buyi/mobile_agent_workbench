# ADR-0001：采用 OpenCode 作为唯一开源底座

日期：2026-10-08。状态：**已接受**。决策依据：用户确认“先用 OpenCode”。本决定选择主工程，不代表任何产品能力或里程碑已经通过实测。

## 决策

采用 [OpenCode](https://github.com/anomalyco/opencode) 作为 Loopit 工作台唯一开源主工程及 Agent 运行时。沿用其 Agent 循环、会话、工具、上下文、服务接口及适用客户端，通过扩展和必要的源码修改补齐 Loopit 交付能力。

四层框架用于映射职责，不要求另建通用控制平台。数据库、调度、客户端与构建技术优先沿用 OpenCode，不预先强制 PostgreSQL、Temporal、Electron 或 React Native。M0 需核实目标版本、依赖和能力，记录最小改造范围。

## 选择依据与取舍

- OpenCode 是完整的开源编码 Agent 工程，根许可为 MIT；拟使用组件及传递依赖仍需逐项核对。
- 已有 Web、桌面及程序化服务接口，预计可减少产品基础建设；这属于工程判断，尚无同条件性能或可靠性横评结论。
- Pi 同样具备完整 Agent、SDK/RPC 和持久化相关能力，但当前方案优先沿用现成产品入口；Pi、DSH、T3 等保留为参考，不作为并行接入清单。
- 覆盖 Codex/Claude 日常场景是能力要求，不等于依赖这两个产品。Claude Agent SDK/Claude Code 专有核心不进入必需执行路径；模型 API 与系统工具的授权另行记录。

资料与许可边界见[参考与选型](../reference-and-selection.md)。

## 扩展边界

| 能力 | 实施原则 |
| --- | --- |
| Agent 循环、编码、会话、上下文、原生工具 | 沿用 OpenCode，不自研第二套编码循环 |
| Web、桌面及连接协议 | 优先沿用；三端状态来自同一底座 |
| 手机 App | 核实可复用路线后补齐，手机网页不代替安装 App 验收 |
| Loopit 设备、构建、发布、监控 | 通过工具扩展接入；旧工程仅是候选，不引入其完整 Agent 运行时 |
| 目标、六环节交付、证据与独立验收 | 在原生对象和扩展点上补齐交付语义 |
| 后台、经验晋升、自主升级 | 按 M2/M3 增量建设，保留独立验证与回滚边界 |

OpenCode 的权限交互不提供 OS 沙盒隔离，无人执行仍需落实工作区、进程、网络、凭据和设备边界。[官方安全说明](https://github.com/anomalyco/opencode/blob/dev/SECURITY.md)

## M0 必须补齐的证据

1. 锁定源码和发行版本、依赖、许可、构建与升级回退方式；本地参考 HEAD 不自动成为采用版本。
2. 输出“沿用 / 扩展 / 缺失”清单，验证底座原生对象与规格合同的映射。
3. 完成停止、恢复、重复派发、未知发布结果、沙盒与证据隔离等真实实验。
4. 验证首个 Loopit 目标的设备、构建及内部分发工具链；记录手机 App 和完整自主交付的未完成部分。

目标功能、验收、平台设备、渠道和预算继续由用户目标及标准确定；采用 OpenCode 不替代这些输入，也不表示 M0 已通过。

## 重新评估条件

若冻结版本存在无法合理补齐的硬缺口，输出失败证据、改造成本与替代方案，记录新的 ADR 后再变更底座。不得静默降低验收要求，也不得通过拼接第二套 Agent 平台掩盖缺口。
