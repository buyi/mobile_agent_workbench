# ADR-0004：本期恢复账本使用本机 SQLite

日期：2026-10-13。状态：**已接受（用户明确变更范围）**。关联：[ADR-0002](0002-delivery-state-on-opencode-store.md)、[执行契约 §7.4](../execution-contracts.md#74-从旧备份恢复)、[M0-F06/A11](../milestones/m0-contracts-and-integration.md)、[S18/P10](../acceptance-spec.md)。

## 决定及原因

用户明确要求不用另一台恢复主机，直接使用本机 SQLite。此前规范将独立故障域作为 M0 前置，现按该授权缩小本期故障范围，复用已有 RecoveryJournal，不另造存储服务。SSH 适配可保留为非必需扩展，不要求其远端部署或认证作为 M0 准入条件。

Task、事件、投影与 outbox 继续使用 OpenCode 业务库。Journal 使用本机另一个受保护 SQLite 文件，保存权威 fence/epoch 和派发预约；它不复制业务投影，且不得与业务快照一起回退。可信宿主固定 Journal 身份和管理权限，Worker 不能直接修改账本、切换 owner 或自行推进 fence。

以下语义保持不变：

- WAL、`synchronous=FULL` 及实际配置读回；事务提交成功后才返回绑定完整意图的 ACK，未获有效 ACK 不派发。
- operation、dispatch 和幂等键不得重复获得许可；超时、异常退出或回执丢失保持未知，不能盲目重试预约。
- 恢复旧业务快照先进入 recovery-only；可信管理边界推进 epoch/generation，旧 token 失效，旧写入者未确认停止时不得新建写入者。
- ACK 只证明持久预约，不证明外部动作成功；渠道与 Supervisor 核对仍必需。日志缺失、不匹配、疑似回退或副作用未知时阻断并隔离，不以新建空 Journal 解锁。
- `journalId` 不能检测同一账本的旧副本；备份/恢复流程必须保留 Journal，不把文件分离误称为硬件故障域分离。

## 本期验证范围

| 范围 | 要求 |
| --- | --- |
| 进程崩溃、服务冷重启 | 必测：提交前、提交后 ACK 前、ACK 后；已确认预约不丢，未知不重派 |
| 恢复旧业务快照 | 必测：保留 Journal，推进 fence/epoch，重放旧 token/操作，核对或隔离外部事实，无第二许可 |
| 日志缺失/身份不匹配 | 必测：拒绝派发，不自动重建账本或把未知当失败重试 |
| 主机正常重启 | 单列待实测能力，不能用进程重启或 WAL/FULL 配置代替 |
| 突然断电、整机/磁盘损坏、异机恢复 | 移出本期保证；需要时另立目标、存储与恢复验收 |

## 对既有证据的影响

旧规格、报告、失败/阻塞结论和摘要按原版本保留。已有本机测试可以逐项映射到新范围，但仍须核对实际部署、身份权限、Journal 不回退及渠道事实；此次决定不直接将 A11 或 M0 标为 passed。完整阶段仍需按修订后的规格装配证据并由独立验收入口判定。
