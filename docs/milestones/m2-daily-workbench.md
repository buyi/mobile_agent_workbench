# M2 日常工作台 v1 规格

版本：v0.3；日期：2026-10-08；状态：评审稿。本文定义待实现和待验收能力，不表示功能已上线或已通过测试。

选型约束：[ADR-0001：OpenCode 单一底座](../decisions/0001-opencode-base.md)。M2 仅在用户已确认、由 M0 锁版并实测的 OpenCode 主工程及其 Agent 运行时上扩展。

依据：[主规格](../loopit-workbench-spec.md)、[执行与交付契约](../execution-contracts.md)、[验收与评测规格](../acceptance-spec.md)、[参考与选型](../reference-and-selection.md)及[里程碑公共约定](README.md)。本文细化 M2，不改变父规格的状态、证据、预算或成功定义。MUST 为强制要求；未冻结配置不得用占位值进入正式验收。

## 1 目标与范围

M2 将 M1 的单功能自主交付链扩展为可日常使用的工作台：浏览器、已安装手机 App、桌面 App 操控同一任务；沿用同一底座的 Agent 执行路径覆盖日常场景；后台准确呈现交付质量、故障和成本；经验能经过评测晋升，也能撤回。

人继续只负责目标、验收与项目执行边界。正常使用不依赖人工搬运上下文、选择下一工具、逐阶段放行、执行命令或救回任务。只读查看不计执行触碰；为完成任务而人工修代码、解锁测试设备、操作安装包或调整状态，均计触碰。

包含九类日常代表场景、三端核心任务操作、长任务与并发隔离、上下文重建、项目知识检索、最小记忆/skill 晋升闭环。“覆盖 Codex/Claude 日常场景”指场景覆盖，不要求接入这两个产品；Claude Agent SDK 及依赖 Claude Code 核心的执行链不作为必需执行依赖。成功标准同时包括交付率、负向用例、平台实测与连续观察，不能只展示一段成功演示。

不包含全部 Codex/Claude 产品功能复刻、任意插件兼容、任意桌面系统、多租户 SaaS、基础模型在线训练。工作台自主修改并升级自身由 M3 证明；M2 自动晋升 skill 不计为自身升级完成。公开商店发布仅在具体目标中要求时执行。

## 2 输入与进入条件

| 输入 | 必须满足的条件 |
| --- | --- |
| M1 交付包 | 真实 Loopit 功能完成，E01–E06 实验符合预期；可追溯候选、最终包、设备证据与观察结果 |
| M0/M1 合同 | 所选底座的会话/工具/事件协议与 Loopit 扩展 schema、验收/证据、沙盒及设备/发布适配已有可重复合同测试 |
| 产品决定 | 核心对象与任务内会话关系有版本化决定；若仍为提案，客户端原型可做，公开协议不可宣称已冻结 |
| 平台计划 | 冻结浏览器、手机 OS/机型、桌面 OS、构建分发方式及自动验收环境；选择一个手机 OS 不代表另一个已支持 |
| 底座计划 | 一个已冻结开源主工程及其单一 Agent 运行时的版本/BOM、许可与分发核验、模型配置与官方支持的认证方式、预算、能力声明、升级回退方案 |
| 验收资产 | 至少 12 个代表任务、固定验收/fixture、平台矩阵、故障脚本、性能基准与 7 天观察规则 |
| 学习策略 | 允许形成经验的来源、作用域、数据保留、候选预算、固定评测集及晋升标准 |

M1 未通过时，可以并行验证同一底座的客户端扩展和工具接入；不得宣称 M2 已进入最终验收。缺失平台、认证或验收定义形成明确阻塞，不能由实现默认值冒充用户已确认的标准。

## 3 四层增量与边界

| 层 | M2 新增 | 所有权约束 |
| --- | --- | --- |
| 接入 | 三端任务列表/详情、目标与附件、证据预览、冲突提示、通知、后台 | 仅缓存投影和草稿；不保存执行锁、发布凭据或权威任务状态 |
| 编排 | 通过底座扩展点补充 Loopit 交付 Gate、恢复核对、统计投影和经验晋升门 | 原生会话/任务/执行状态沿用底座；Loopit 仅记录交付增量事实与原生对象映射，不建并行通用调度器 |
| 执行 | 沿用底座工具体系，接入 Loopit 设备、独立日常验证器和经验评测 | 规划、诊断、工具选择与编码循环由同一底座完成；不建立多 Runtime 适配框架 |
| 基础 | 基于底座认证/存储/连接机制补充产物预览、经验版本、通知与指标 | 先复用底座能力；缺失部分使用最小扩展，工具仍受隔离、设备/发布授权与总预算约束 |

优先沿用底座现有客户端、公开协议和连接实现；三入口的缺口使用薄客户端或平台壳补齐，不另建一套通用客户端 SDK/控制协议。交付对象在底座原生会话与事件上建立映射，只有验收、证据和指标等增量需要扩展字段。平台 API、通知和文件选择封装在接入层；设备驱动通过底座工具接口接入。

| M2-F03 | 手机挂起、客户端退出、连接断开不终止 Worker；通知来自持久事件 | 后台继续运行；完成通知可跳转同一 Task，拒绝通知权限时仍可查询结果 |
| M2-F04 | 锁定的单一底座通过原生会话生命周期、沙盒、停止/恢复与计量合同；执行链不以闭源 Agent 核心作为必需依赖 | 一套底座/运行时 BOM、能力矩阵、许可核验与测试报告；不支持的能力显式拒绝 |
| M2-F05 | 同一底座的 Worker 重连/故障恢复符合目标能力、策略与预算；替换 Worker 前核对旧执行停止 | 原目标/候选/证据/预算保留，按底座原生恢复方式继续或记录新 Attempt；不引入第二运行时 |
| M2-F06 | 支持第 6 节代表任务并合法短路六环节；输出有来源和对应验收 | 只读任务不强制构建；UI/移动任务不能省略必需设备证据 |
| M2-F07 | 支持受控并发、长会话、暂停和故障恢复 | 写副本、设备、凭据不串扰；压缩/同底座恢复后关键事实和目标版本可重建 |
| M2-F08 | ContextManifest 记录输入来源、候选、策略、有效指令/skill 版本和检索结果 | 项目知识按需检索；原始证据可回溯；全局个人配置不隐式泄漏 |
| M2-F09 | 记忆有来源、作用域、版本、可信状态、有效期与撤回状态 | 冲突时重查当前事实；撤回后后续检索与缓存不返回该版本 |
| M2-F10 | skill 从候选到评测、小流量和激活有自动门；回归候选被拒绝 | 固定基线/候选对照、反例、晋升回执和可执行撤回记录 |
| M2-F11 | 自有后台提供总览、队列、运行、失败分类、资源、费用、验证质量与经验版本 | 每个指标显示分母和窗口，可下钻到 GoalRevision/Run/Attempt 与证据 |
| M2-F12 | 浏览器、文件、MCP/skill 工具具备能力探测、版本、权限与失败隔离 | 工具文本不能修改验收；越权拒绝；安装/升级失败能回退固定版本 |
| M2-F13 | 事件流背压、产物按需读取、日志/差异分页、客户端长列表虚拟化 | 按 P01–P10 报告分位数和资源；大文件不阻塞任务控制 |
| M2-F14 | 旧客户端/协议明确降级；服务端升级保留已有任务事实 | 未知能力不可误发；客户端更新不更换 Run owner；旧历史可读取 |

三端每次命令、查询、事件订阅和产物获取都校验操作者、项目和资源权限，连接已认证不代表方法已授权。缓存和离线草稿按账号/项目隔离；会话失效或账号切换后撤销旧订阅、清理受保护缓存，不继续显示前账号材料。通知载荷仅包含允许展示的摘要和受控引用，不携带凭据或敏感原始证据。

同一底座的 Worker 恢复优先使用其原生会话恢复机制；不支持时，只能在该底座内按已持久化事实重建，并明确记为重建。原进程未停止、外部作业未核对或权限不等价时不得替换执行者；保持 recovering/blocked 并继续其他独立任务。恢复后的失败和成本汇总到原 GoalRevision，不复制未公开的原生私有内存。

## 5 端与能力矩阵

### 5.1 客户端矩阵

| 能力 | 浏览器 | 已安装手机 App | 已安装桌面 App |
| --- | --- | --- | --- |
| 目标、附件、修订、暂停/恢复/取消 | 必需 | 必需 | 必需 |
| 进度、验收、证据、交付物 | 完整浏览 | 核心预览与安全打开/下载 | 完整浏览与代码差异 |
| 断网、并发修订、旧客户端 | 必测 | 必测，含 OS 后台挂起/恢复 | 必测，含应用关闭/重开 |
| 结果通知 | 应用内通知 | 原生通知及点击定位；拒绝权限降级 | 应用内通知，系统通知按冻结范围 |
| 后台统计与运行下钻 | 完整 | 任务状态、结果与关键指标 | 完整或内嵌同源管理页面 |
| Worker 接入 | 查看和管理已授权节点 | 远程控制，不在手机执行构建 | 本机节点接入与健康查看 |

手机网页、PWA、桌面浏览器的窄屏模拟不能替代手机 App 验收。M2 冻结支持的 iOS/Android 组合和桌面系统；所有已声明平台必须逐一实测，未选择的平台显示计划中/未验证，不标支持。工作台手机客户端与受测 Loopit App 分别记录平台，不能互相代替证据。

### 5.2 单一底座能力矩阵

| 能力组 | 同一锁定底座的要求 | 宣称支持所需证据 |
| --- | --- | --- |
| 问答、代码修改、Review、文件、长任务 | M2 必需核心 | 每项场景由该底座完成，不以另一 Agent 产品结果补位 |
| 结构化事件、工具调用、权限、预算、取消 | 必需；沿用原生接口并最小补齐交付约束 | 合同测试；停止包含子进程与设备动作核对 |
| 图片、浏览器、MCP、移动工具、构建/发布 | 按冻结任务、模型配置和平台声明 | 该底座覆盖每项全局必需场景；声明支持的组合均实测 |
| 原生 resume、checkpoint、steer | 探测后声明 | 原生不支持时可声明同底座内事实重建；不得宣称原生恢复 |
| 客户端重连与同底座 Worker 恢复 | 必需 | 原目标与候选保留、旧执行停止、证据有效性与费用连续性实测 |

模型供应商或模型配置变化不等于新增 Agent 运行时；配置能力和成本差异须独立记录，不能用切换模型规避底座能力缺陷。矩阵状态使用 supported / limited / unsupported / unverified，记录版本、平台、验证报告和限制。只有当前组合已通过合同与场景实测才为 supported；limited 不得自动满足要求完整能力的目标。

## 6 日常场景数据集

以下是待冻结的最小任务构成，具体仓库基线、输入、验收标准与预算须在运行前填实。D01–D12 为稳定 case ID；每个用例保留独立 Task/GoalRevision 评测身份，三次重复以 evaluationSampleId 和 Run 区分。

| ID | 代表任务 | 核心验收产物 |
| --- | --- | --- |
| D01 | 仓库代码问答与调用关系调查 | 引用可解析的答复；无意外写入 |
| D02 | 有明确行为标准的小功能 | 候选、适用测试、交付报告 |
| D03 | 可复现 Bugfix，首次验证失败后修复 | 失败、诊断、新候选与重验链 |
| D04 | 保持行为的局部重构 | 差异、固定回归、范围遵循 |
| D05 | 图片/设计输入驱动 UI 实现与 Loopit 设备验证 | 设计依据、最终包身份、真实 App 证据 |
| D06 | 对冻结候选做独立 Review | 代码定位、可复现 finding；受审候选未被修改 |
| D07 | 基于资料生成文档或数据分析文件 | 可打开产物、来源、合法短路回执 |
| D08 | 浏览器检索并完成授权页面操作 | 网页来源、操作与副作用回执、权限边界 |
| D09 | 使用一个版本化 MCP 工具及按需 skill | 能力发现、工具结果、失败隔离与版本引用 |
| D10 | 触发会话压缩的长任务与中断恢复 | 关键事实重建、目标不漂移、同一 Run 延续 |
| D11 | 并发两个仓库候选并竞争同一设备 | 工作副本隔离、串行设备租约、取消/恢复记录 |
| D12 | 内部部署观察及可恢复健康故障处理 | 指标窗口、恢复生效、新验收和最终健康交付 |

D12 的通过必须是预先定义的最终恢复与健康目标满足；单纯正确阻断发布属于负向套件通过，不能计作业务交付成功。D11 每次样本含两个受控子任务，其共同预算和总成本归入该样本，不拆分成两次成功提高分子。

### 6.1 样本、分母和单一底座覆盖

1. 至少冻结 12 个任务，每个独立运行 3 次，最低计划样本 N=36；输入基线重置，保留每次 seed/环境。修复 Attempt 属于原样本，不新增成功样本。
2. 全部样本使用同一个冻结底座与 Agent 运行时版本，提前指定模型配置、平台、执行顺序和截止时间；配置可有差异，但不得在结果出来后更换分配以补过。
3. 该底座必须运行全部 12 类任务；每个已声明的平台/模型能力组合均需实际证据。36 次可以包含这些组合，但同一次运行只计一个交付样本；缺少组合覆盖须提前扩展计划或单列补充合同样本。
4. 总体无人验收通过率 = 在预算内完成全部必需 Gate 且执行触碰为 0 的样本数 / 全部预注册交付样本 N。最低 36 次须至少 29 次通过。按平台和模型配置分别报告分子、分母、场景覆盖和失败；不宣称每个配置均有三次重复，除非实际执行。
5. 失败、阻塞、取消、超时、被取代、人工救回均保留在 N 且不进入无人成功分子；截止仍活跃、排队、暂停和未运行同样不通过。环境原因分层标记，不从交付率中剔除。superseded 只用于尚未结案的旧目标，已成功/失败/取消的历史结果保持原值。
6. 所有预注册样本必须实际尝试；存在 notRun 时，M2 验收不完整，即使已运行部分达到 80% 也不能退出。补跑使用新 sample ID，不能覆盖失败；扩展验收 cohort 必须保留原 cohort 与合并结果。
7. 负向、安全、平台合同和学习实验单列套件，不混入交付率分子；同一原始运行符合多个检查时可引用证据，统计仍只算一个交付样本。

报告同时展示 12 个 case 各自的 0/3–3/3 结果、Run 级总体结果、按模型配置/平台分层结果与人工触碰。36 次只证明初始工程门槛，不作为生产可靠性估计。

## 7 上下文、记忆与最小学习闭环

工作记忆随 Run 恢复；情景/语义/程序记忆按项目与策略检索。模型只提出候选经验；存储、授权、版本、撤回和晋升由 harness 执行。当前代码、目标与设备事实优先，历史经验不能覆盖它们。

最小闭环使用一次真实失败修复作为来源，自动形成包含适用条件、反例和证据的候选 skill。在授权的经验改进目标下运行固定对照评测，满足门槛后进入限定任务/范围的 canary，再激活；不满足或证据不足保持候选/拒绝，不要求人手工批准每次晋升。M2 必须实际证明一个有收益的候选完成晋升；若未找到满足条件的候选，学习验收尚未完成，不能放宽门槛补过。

| 阶段 | 输入 | 输出与门槛 |
| --- | --- | --- |
| 提案 | 运行轨迹、失败和修复证据、父目标、预算 | ImprovementProposal、来源与授权范围；无凭据/敏感值 |
| 评测 | 固定 skill 候选、旧版本/禁用经验基线、隔离任务集 | 至少 10 个固定任务，每个基线与候选各 3 次，至少 60 次；完整保留失败 |
| 判定 | 成功/误通过、耗时、成本及按任务配对结果 | 无新增关键误通过或越权，成功率不低于基线，成本或时延有可复现收益 |
| 小流量 | 已通过候选、预注册任务数/窗口/停止阈值 | 独立预算下的运行报告；指标不足不晋升，回归即撤回 |
| 激活/撤回 | 有效评测和 canary 证据、版本与作用域 | 晋升回执或撤回回执；后续检索缓存失效，历史 Run 引用保留 |

“可复现收益”的指标、最小改善值、配对统计方法及 canary 样本数在实验前冻结，不在看到结果后挑指标。报告样本、方差、任务聚类和费用缺失；无法判断收益则维持候选，可在预算内追加预注册样本。

训练/归纳来源不得泄露固定验收集；Builder 不得修改评测标准或隐藏反例。至少注入一个训练样本有效、固定验收集回归的 skill，证明拒绝晋升；另注入错误记忆，证明撤回及跨项目隔离。

M2 需要最小实验记录、skill 版本和评测入口。M3 在此基础上扩展实验注册、数据集快照/导出、策略或模型候选管理，以及工作台代码升级；M2 不承诺基础模型自动训练。

## 8 后台与连续观察

后台按[主规格第 9 节](../loopit-workbench-spec.md#9-自有后台与指标口径)计算：GoalRevision 入队 cohort 是稳定分母；Run、Attempt 独立统计。显示 S/F/B/C/U/A/Q/H 全部状态、已结案成功/失败率、截止交付率、无人交付率、自修复、误通过覆盖、耗时、成本及资源健康。

每项指标必须带公式版本、过滤条件、截止时间、分子分母与数据新鲜度；可从事件重算并下钻。模型可解释失败原因，不临时生成指标真值。费用未知显示 unknown；失败后成功、目标修订和人工救回不删除历史。

连续观察采用冻结候选版本进行 7×24 小时，覆盖上述至少 36 个预注册代表样本，建议分布为 6/5/5/5/5/5/5，每天均有真实执行。额外自然任务全部进入运行统计，并与固定评测 cohort 分开；不以空闲 7 天替代运行观察。

观察期记录所有服务/Worker/客户端故障、外部依赖故障、恢复和资源变化；故障注入窗口有标签但保留原始可用性和用户交付影响。出现任务丢失、关键误通过、越权、重复副作用或持续资源泄漏，必须修复并重新开始受影响候选的观察，保留失败窗口。7 天不能外推月可用性实绩。

## 11 交付、退出与 M3 交接

交付包 MUST 使用[公共 MilestoneManifest](README.md)索引，包含：冻结 spec/决策记录、三端安装与发布清单、单一底座与 Agent 运行时 BOM、许可核验和能力矩阵、原生协议/扩展 API 兼容说明、所有验收 result/events/artifact-manifest/metrics/human-interventions、后台指标定义与重算工具、学习基线/候选/撤回记录、7 天观察与备份恢复报告。verdict 使用 passed/failed/blocked；必需项 notRun 不可 passed。

M2 退出必须满足 M2-A01–A10，所有必需平台和单一底座核心场景完整覆盖，至少 36 个交付样本达到门槛且无未运行项，独立负向用例全部通过。存在未确认能力只允许保留为非承诺扩展；不能把三入口、单一底座的日常场景覆盖或最小学习闭环降级为可选项后宣布完成。

交给 M3 的输入是可稳定运行的工作台版本、可重放历史与升级兼容基线、可观察的目标缺口、已验证经验晋升机制、评测集/数据权限、预算、Supervisor 发布回退接口及隔离演练环境。M2 交付接口和演练基础，不要求先完成自主升级；M3 再以用户长期目标为根，创建有界改进 Task 并验证一次工作台自身功能升级及失败回滚。
